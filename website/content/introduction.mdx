The `tinkle.v1` package is the public Protobuf contract of the Tinkle messaging
API. Its single source of truth lives in this repository under
[`tinkle/v1/`](https://github.com/tinkle-org/schema/tree/main/tinkle/v1) —
there is no upstream mirror; every contract change is authored here.

## What is published where

| Layer | Location | Rebuilt on |
| --- | --- | --- |
| Protobuf source | `tinkle/v1/*.proto` in this repo | Commit |
| Validation (lint/format/breaking/build) | GitHub Actions on every PR | Every push |
| Schema distribution (Go/Rust SDKs) | [Buf Schema Registry](https://buf.build/tinkle-org/schema) | Release PR merge |
| This documentation site | Generated reference served by the main website at `tinkle.me/schema/` | Website image build |

The Buf CI workflow validates every PR and posts a summary, and publishes merged
`main` changes to the BSR; `v*` tag pushes publish version labels.
[release-please](https://github.com/googleapis/release-please) manages versioning
and release tags.

The [schema reference](/schema/reference) is produced from the protobuf
descriptor set, including source comments, deprecations, and reserved
definitions, on every site build. Edit `.proto` doc comments to change the
reference and `website/content/` for schema overview pages.

## Schema scope

The package defines authentication, accounts, users, contacts, messaging,
channels, bots, stickers, and help APIs, with shared types in `common.proto`.
[`updates.proto`](https://github.com/tinkle-org/schema/blob/main/tinkle/v1/updates.proto)
defines `UpdatesService`: `ReadUpdates` returns a replay page,
`FollowUpdates` streams individual durable updates, progress, and rebuild signals, and
`ObserveConnectivity` streams ephemeral per-user `ConnectivityChanged` events.
See the [reference](/schema/reference) for the contract details.

This repository documents the transport-independent schema. Runtime transport
bindings belong in their implementation repositories. Public UpdatesService
bindings are not implemented in Chorus; internal replay, watch, and presence
capabilities exist.

## Repository layout

```
tinkle/v1/        authoritative .proto sources
conformance/      schema + codec checks (pure Python, no bindings)
buf.yaml          v2 module config
website/          docs content sources + generators (rendered by the main website)
.github/          workflows: buf-ci (validate), release-please, docs-ci, docs-build
```

## Status

The contract is **pre-release**. `buf.yaml` disables builtin breaking checks for
`tinkle.v1` restructuring; the intended stable policy is `breaking: FILE`, to be
re-enabled at the first stable release. Until then, structural churn and no
external compatibility commitment are expected. The generated reference follows
`main` and may be ahead of the latest published SDKs.
